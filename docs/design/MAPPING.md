### Foundations findings

- **`design/` is excluded (PR 2a, D4).**
  - It is committed on the integration branch, excluded from `tsconfig.json`, the ESLint `ignores` and `.prettierignore`.
  - `assetBundlePatterns` is narrowed to `assets/**/*`.
  - dependency-cruiser rule `no-design-export-in-the-app` fails any import of `design/` from `app/` or `src/`.
  - Metro only bundles what is imported.
- **Icons:** PNG icons tinted to the theme colour (D1, PR 2b).

### How the splash works today

Explanation only; nothing is changed until the owner has read it (PR 2d).

- **Config.** `app.json` has a top-level `"splash": { "image": "./assets/splash.png", "resizeMode": "contain", "backgroundColor": "#F4EFE7" }`.
  - `assets/splash.png` has never been in git. It is in the template's first commit (`f30c9b90`) and was never added.
  - The tracked file is `assets/splash-icon.png`, and nothing references it.
- **Nothing reads that key.** Since SDK 52, the splash is configured by the `expo-splash-screen` config plugin.
  - That package is not installed. It is not in `package.json` and not in `node_modules`, although SDK 57 lists `~57.0.9` in `bundledNativeModules.json`.
  - `@expo/prebuild-config` in this repo has no built-in splash handler.
  - `npx expo config --type introspect` shows the `splash` key passed through untouched. No plugin in the list handles it. The only splash entries in the generated native config are the template defaults: iOS `UILaunchStoryboardName: SplashScreen` and Android `@style/Theme.App.SplashScreen`.
  - Because nothing resolves `./assets/splash.png`, the missing file never failed a build.
- **What builds show.** The template's default launch screen, without the Moraki image and without `#F4EFE7`.
  - This is inferred from the config. The owner can confirm it from what TestFlight build 2 shows on launch.
  - The background colour in `app.json` is likely unused as well.
- **Consequence for PR 2d.** Day and night splash screens on `#E9EDE6` / `#131814` need the `expo-splash-screen` plugin, which is a new dependency.
  - It is an Expo SDK module (version `~57.0.9`) and needs a native rebuild.
  - PR 2d asks for a yes before adding it. Without it, PR 2d changes the app icon, adaptive icon and favicon only.

### The name in Greek

Greek inflects names (genitive, accusative), and the app does not know the baby's gender. So a template that substitutes `{{name}}` into a sentence cannot be translated word for word. Every key that puts the baby's name in a sentence follows this rule:

- The Greek keeps the name in the nominative, unchanged.
- The name stands as a label (`Εβδομάδα · {{name}}`), after a colon or dash, or in a vocative-free form that works for any name. Otherwise the wording avoids the name.
- The English may differ in structure from the Greek.
- Each PR lists every such key, EN and EL side by side, for the owner's review.

Existing keys already put a name inside a Greek sentence with a gendered article and the name in the nominative. Examples are `του/της {{name}}` and `τον/την {{name}}` in `settings.otherAccount.body`, `settings.localEntries.body*`, `join.alreadyIn`, `settings.roles.remove` and `settings.roles.whatTheyCanDo`. The refresh does not change these. They are listed in PR 2a for the owner's review, because they read awkwardly for most names.

Copy in health contexts is checked against rule 10 (nothing that interprets data). `copyRules.test.ts` already enforces part of this.

## Decisions (approved 2026-10-09)

- **D1, icons:** PNG icons (`design/ui-icons/png-ink`, 96 px) tinted to the theme colour, through one `Icon` component so SVG can replace it later. No `react-native-svg`. Checked for sharpness at 3x in both themes.
- **D2, Home:** the 06 tile layout. The time-since-feed card is styled like the 07 timer card, without the ring.
- **D3, error colour:** `palette.invalid`, retuned to Sage.
  - Day `#8E4434`, at least 5.0:1 on every Sage surface.
  - Night `#DDA08F`, at least 5.3:1.
  - Both are checked in `contrast.test.ts`, and the colour is always paired with text or an icon.
- **D4, `design/`:** committed on the integration branch and excluded from builds and checks (section 1).
- **D5, sheets:** `formSheet` with a 32 corner radius, as its own commit in PR 3c-1.
  - Tested with the keyboard open, at 200% text, and on iOS and Android.
  - The fallback is the current modal with a 32 top radius.
- **D6:** step 2 is four PRs: 2a tokens, 2b icons, 2c components, 2d app icons and splash.
- **D7:** the touch target stays 48.
- **D8:** Settings keeps its inline cards and is restyled only.
- **D9:** design conflicts follow `theme.ts`, then `brand-guidelines.md` where `theme.ts` is silent. Each PR lists the conflicts it resolved.
