# Sage design refresh: mapping

Step 1 of the Sage refresh. This document describes what exists, what the design shows and how the two meet. No source file changes with it.

Sources: `design/` (Sage v1.0 export), the root `CLAUDE.md` (which wins on any conflict) and the code on `main` at `2996b7fc`.

Where `design/CLAUDE.md` and the owner's brief disagree, the brief wins:

- This file lives at `docs/design/MAPPING.md`, not `design/MAPPING.md`.
- The app uses the system font. Ysabeau Infant and Commissioner are not loaded.

### Foundations findings to handle in step 2

- **`design/` would leak into checks and possibly the bundle.**
  - `tsconfig.json` includes `**/*.ts`, so `design/guidelines/tokens/theme.ts` is typechecked and linted. ESLint has no `design/` ignore.
  - `.prettierignore` has no `design/` entry either.
  - `app.json` has `"assetBundlePatterns": ["**/*"]`.
  - Step 2 adds `design/` to the tsconfig `exclude`, the ESLint `ignores` and `.prettierignore`. It narrows `assetBundlePatterns` to `assets/**/*` (this touches the app config only; flagged for review). Metro only bundles what is imported, and nothing will import `design/`.
- **Splash file.** `app.json` points at `./assets/splash.png`, which is not in git. The tracked file is `assets/splash-icon.png`. The step 2 asset swap fixes the reference.
- **Icons need a rendering decision** (see section 7, decision D1).
- **Committing `design/`.** It is untracked (7.7 MB, mostly screen PNGs). This PR leaves it out. See decision D4.

## Decisions needed before step 2

- **D1, icons.** `react-native-svg` is not installed.
  - (a) **Recommended:** render the design's PNG icons (`png-ink`, 96 px) with RN `Image` and `tintColor` from the theme. No dependency, works in the current dev client, and follows the theme like `currentColor`. Cost: 23 PNG files (~1–2 KB each), and the strokes cannot change per size (the design varies stroke from 1.4 to 1.8 by size; one stroke weight is fine).
  - (b) Add `react-native-svg` (Expo SDK module, about 1 MB native code). Needs a new dev client build, which means a native build while builds are on hold.
- **D2, Home layout.** **Recommended:** 06 tiles, with the app's existing timer card styled as the 07 hero card but without the ring. The app's Home leads with "time since last feed", and the design itself suggests 07 if it suits.
- **D3, error colour.** Sage has no error colour; the app shows validation in `invalid` (muted clay). Recommended: keep an `invalid` token tuned to pass AA on both Sage backgrounds. It is always paired with text and `accessibilityRole="alert"`, never used on a health number.
- **D4, committing `design/`.** Recommended: commit it on `design/sage-refresh` so later sessions and reviewers have the reference (7.7 MB, excluded from builds and checks in step 2). The alternative is to keep it local only.
- **D5, sheet shape.** The log forms are `presentation: 'modal'` routes. Recommended: switch them to `presentation: 'formSheet'` with `sheetCornerRadius: 32` and the grabber shown (react-native-screens, already installed). This changes presentation only, not routes or behaviour. It needs a check on Android and with the keyboard.
- **D6, step 2 split.** Four PRs (recommended, keeps the 400-line rule) or one PR.
- **D7, touch target.** The app's token is 48 (SDD section 8); the design's minimum is 44. Recommended: keep 48.
- **D8, "Settings" structure.** Keep inline cards (recommended; no new navigation). Drill-down rows like 19 are logged as design only.
- **D9, small design inconsistencies.** Recommended: follow `theme.ts` in each case.
  - `ui-kit.html` labels night chip `#2E3830`; `theme.ts` says `#2A322C`.
  - `ui-kit.html` gives sheets 28 at the top; `theme.ts` and the screens use 32.
  - The night welcome wordmark is `#EFE4D4`, which breaks the never-recolour rule.
  - Back buttons are 48 on screens and 46 in the tokens.
  - Several sizes in screens are not in the type scale (40, 34, 30, 38, 50, 66).
