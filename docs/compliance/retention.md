# Retention policy

**Task:** P4-11. **Written:** 2026-09-26.

Storage limitation (Article 5(1)(e)) means naming a period for every category and
being able to point at the mechanism that enforces it. Where a mechanism does
not exist yet, this document says so instead of implying it does.

---

## What a person can get today, and what they cannot

| Right                             | State                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Access, portability (Art. 15, 20) | **Works.** Settings → Data export → Export my data exports the current baby's entries as JSON and CSV. Deleted entries are not included (P4-05). Once #202 lands, the JSON also has the signed-in person's own account section: email, sign-in methods, consent records and the feedback they sent. Anything else goes through the data-request procedure (`docs/compliance/data-requests.md`, P4-F2)          |
| Rectification (Art. 16)           | **Works.** Every entry is editable, and the baby's details are correctable by any writer                                                                                                                                                                                                                                                                                                                       |
| Restriction (Art. 18)             | **Partly.** Withdrawing consent stops this account's new entries syncing. Nothing already stored is deleted, reading the household's data is not gated, and an entry already shared can no longer be edited or deleted from the server by the person who withdrew (the events policies require consent for any update, including a soft delete). The consent text says so since 2026-10-18                     |
| Erasure (Art. 17)                 | **Works.** Settings → Leave or delete (P4-06): leave a household, delete a household (owner), or delete the account. A household with no one else in it goes with the account; a shared one stays with the other caregivers, the person's name and auth record removed, and ownership handed to a member the person chooses (decision D3). Their entries there keep an author id that no longer maps to anyone |
| Objection (Art. 21)               | withdraw consent, or stop using the app; there is no profiling and no marketing to object to                                                                                                                                                                                                                                                                                                                   |

The consent screen's copy was corrected in P3-F6 so it would not promise
deletion the app could not perform. P4-06 restored the promise in the same
change that built deletion: the consent screen now points to Settings → Leave
or delete.

## Server backups (decided 2026-10-24)

- **Plan:** production runs on Supabase Pro from launch.
- **Daily backups:** whole-database snapshots, kept for 7 days according to Supabase's Pro plan documentation. Confirm in Supabase → Database → Backups.
- **Point-in-time recovery:** not enabled (paid add-on).
- **Deleted data:** it leaves the backups as they age out, at most 7 days after deletion. Data can't be removed from a backup selectively.
- **Privacy policy:** should say this. The lawyer reviews the wording.
